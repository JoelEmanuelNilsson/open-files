## Engineering

Solve the system, not the result — results are datapoints. Fixes
generalize or they don't ship: make the error class impossible by design.
First principles; existing code, docs, and rulings are datapoints, not
truth. Production-grade or no implementation. Complexity must solve a
real, repeated problem — one good solution. Find the true limits from
first principles, declare them, live with them; state only those.
Refactor to the principle first, then change behaviour, as separate
commits. DRY means one authoritative home per piece of knowledge, not
per similar line. When principles collide, pick the one that cuts future
cost in this codebase.
