Why does my pi transcript look uglier than Claude Code's, and what makes it stop?

Our own rows already have Claude Code's shape. Every ugly line is one of three things: a row that never got our receipt, a bug that stops bash from folding, or a stub pi will not let us silence.

Why bash never folds: it asks the wrong copy

pi loads every extension file in its own module cache. bash.ts borrows the receipt from the transcript folder, and gets a second copy of the planner with it. That copy is empty. derived · loader.js:417, group.ts:211, live repro

Two files, two loads. Same source, different memory.

The planner fills copy 1. Copy 2 is never written to.

Bash asks copy 2. Told "row", it draws itself. The read beside it hides and no line replaces it.

The tests are green because they load every file through one cache. Fix: planner state on the process, the way click.ts keeps its patch, and a test that loads files the way pi does.

Two smaller rules stop the rest from folding

A lone call never folds: group.ts:232 keeps a settled group of one as a full row. Claude Code folds it to Ran 1 shell command.

The prose rule counts a hidden thinking block as speech, so it ends the group. Claude Code skips thinking blocks. With hidden thinking on and a thinking model, nearly every call is alone in its group. derived · group.ts:538

Why the agent rows are wide open: they never got the receipt

A tool row pi draws itself sits in a padded box under a spacer: three blank lines. A row with our receipt draws exactly one. pi-subagents draws the launch row and the completion notice itself, and gives get_subagent_result no renderer at all. derived · tool-execution.js:44,48,197

The kit cannot take those rows today because of one rule and one array:

NOW
pi-web-search→@tintinweb/pi-subagents→~/dotfiles/pi/kit→plannotator
TARGET
pi-web-search→~/dotfiles/pi/kit→@tintinweb/pi-subagents→plannotator

First wins: whoever registers a name first keeps it. The ring marks who owns Agent. Flip two lines in settings.json. derived · runner.js:324

What the flip also changes

Shortcuts are the opposite rule, last wins, and terminal-input listeners run in load order. After the flip pi-subagents wins a shortcut collision, and the kit sees ↓ before the vendor's list does. Both are fine once the vendor's list is off.

Why Thinking... stays: pi draws it, not us

The thinking stub is pi's own line. An empty label still draws two blank lines: pi wraps even nothing in colour codes and counts it as content. Zero needs a patch on pi's component, and a PR upstream so the patch can go. derived · assistant-message.js:74,109 · ran it
